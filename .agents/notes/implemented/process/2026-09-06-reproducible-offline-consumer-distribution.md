# Distribuir el runtime como generación gobernada y reproducible

AGENTS.md, MIGRATION-01, `bin/ARCHITECTURE.md` y el plan de distribución autorizan un único perfil `autonomy-runtime.v1`. El manager usa sólo Python estándar y obtiene del mismo SHA Git los módulos QO de producción, sus contratos y schemas, el manager, bootstrap y schema de instalación. Verifica los archives locales de `yaml` y `zod` contra el lockfile y genera un manifest canónico sin fechas ni paths locales. Un bundle candidato o un tag local siguen sin ser prueba de publicación.

La instalación mantiene sus payloads y registros bajo `.harness/distribution/`; la única escritura externa es el `lockPath` absoluto del directorio Git efectivo que el propio plan declara, incluso para worktrees enlazados. Ese archivo se abre sin seguir enlaces, debe ser regular con un solo link y no se trunca: `flock` aporta ownership de proceso. Prepara una generación por digest, verifica path, tipo, link count, modo y hash, y conmuta sólo `active.json` mediante reemplazo y fsync. Plan y upgrade-plan no escriben; apply, upgrade y rollback requieren el digest exacto aprobado, revalidan bajo lock exclusivo e inmediatamente antes del selector, y dejan intento/transacción/receipt. Un postverify fallido restaura el selector anterior y conserva evidencia. Cambios incompatibles de major o de cualquier payload estable, incluido bootstrap/schema, fallan con `MIGRATION_REQUIRED`; no hay migraciones ejecutables arbitrarias.

Las generaciones se sellan read-only. Como Git sólo transporta el bit ejecutable, `verify` y los comandos de plan aceptan en modo lectura exclusivamente la normalización versionada 0444→0644 o 0555→0755 cuando el SHA256 y la entrada del índice coinciden; el bootstrap vuelve a sellar el modo declarado antes de cargar el runtime. La `.gitignore` interna exceptúa únicamente `generations/*/runtime/node_modules/**`, haciendo versionable el cierre offline aunque el consumidor ignore `node_modules/` globalmente.

Todo fuera del namespace, salvo el lock Git exacto declarado, continúa consumer-owned. Se preservan la configuración, estado, journals, oracles, receipts, feature/progress/decisions y un runtime legacy paralelo; no se crea baseline, autoridad ni `ACTIVE`. La prueba E2E versiona sólo el namespace instalado, clona de nuevo, vuelve inaccesibles source y bundle, deja cache npm vacío y ejecuta `identify` con el runtime real y `yaml`/`zod` reales bajo autoridad efímera explícita. Reconsiderar este diseño al introducir otro perfil o una migración compatible de bootstrap/schema; ambos quedan fuera del alcance actual.
