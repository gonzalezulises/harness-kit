# Approved execution backends preserve intent and require observed provenance

F24 extends the optional autonomy runtime with one closed GitHub Actions
connection. It keeps the existing controller and persistent journal, uses
unchanged reserve/outcome events, and signs narrowly scoped standalone budgets.
This avoids inventing remediation defects, a provider framework, service,
database or scheduler merely to execute an approved review/release obligation.
The exact host workflow and enrolled execution-supervisor issuer bind observations
to original request, immutable workflow revision, run, attempt and output.
Uncertain effects keep their key and charge; they cannot redispatch or settle
through generic reconciliation. Concurrent identical requests share one intent.

H07 now has authenticated catalog discovery, an exact-shadow review dispatch and
strict local finding validation backed by private verified journal provenance.
The concrete pinned Codex app-server worker observes account/catalog, thread,
turn, final output and process exit. The operator supplies actual tested Linux
isolation, dependency image custody and model-only authentication. The worker's
read-only flags and process-group cleanup are deliberately not advertised as a
portable sandbox. No generic helper signs a supplied PASS.

H08 derives observations only from those verified records and executes one
obligation at a time. Artifact acceptance binds the latest review evidence;
deploy/rollback require separate typed approvals and actual authenticated target
readback; smoke and observability remain distinct executions. Existing consumer
workflow code supplies the target adapter and checks. Larger source transfers
than the bounded inline descriptor, additional artifact origins and workflow
reruns are unsupported until a concrete need warrants review.

This decision follows AGENTS.md, docs/quality-document.md and
`docs/implementation/2026-09-05-harness-hardening/runtime-boundary-review.md`.
The executable contract is
`packs/autonomy/repo-template/scripts/quality-orchestrator/contracts-execution-v1.md`.
Historical H07/H08 contracts, tests and evidence remain diagnostic baselines.
New offline tests exercise the positive transport/provenance path and local
stdio worker; they do not prove live Codex containment or production deployment.
The cancelled authenticated preflight and interrupted broad review remain
untouched. Revisit the host integration only when an actual operator workflow,
contained session and target have separately authorized live acceptance.


The first scoped review identified four functional defects; fix-1 retains the
real deployment intent key and adds a separately authorized readback of a known
terminal deployment, checks supervisor enrollment before spending, reconciles
reviews using their reservation-time catalog binding, and decodes worker UTF-8
incrementally with fatal EOF validation. Failed or expired deployment evidence
is preserved. Readback is a fresh budgeted observation, never a retry of the
uncertain deployment effect. The six covering RED assertions and focused GREEN
results live under the F24 `fix-1` evidence directory; no broad review was resumed.
