# Apply live gates and retain the boundaries of the evidence

AGENTS.md and DECISIONS.md (MIGRATION-01) govern this change. The full harness now runs its versioned quick registry against the current target before project/pack verification. An explicit installation profile declares applicability: kit release metadata is kit-only; every applicable full-consumer gate remains required. Minimal is a contract scaffold and never claims full mechanical readiness.

Protected CI policy and judge files remain in a separate base checkout. Commands execute against the exact candidate checkout through the target-root interface; the workflow records identities and requires an observed live-gates zero. Missing protected profile/judge contracts are ADOPTION_REQUIRED. Candidate policy cannot select a permissive judge. The protected judge also selects its own pinned parser and uses isolated Python imports so candidate modules or tool directories cannot replace the checker. The old approach of copying base verifiers into head invalidated source identity and is removed. Bootstrap requires an owner-controlled protected-policy adoption, described in docs/harness-capabilities.md; merging a failed required check is not a bootstrap.

Repair prose no longer changes command identity; command bytes and every other layer field remain exact, and each claim is rerun. The hook formats a regular-file snapshot of the index, rejects symlinks, atomically replaces only the verified index after checking for concurrent edits, and leaves working-tree bytes intact. A formatter error blocks. This trades automatic working-copy synchronization for preserving partially staged intent; selected formatting differences can be reviewed after the commit.

Oracle YAML uses pinned PyYAML6.0.3 with duplicates, anchors/aliases, unsupported tags and invalid shapes rejected. Full consumers install the parser into an isolated tools environment. A witnessed local receipt binds exact tests, source snapshots, argv, nonzero exit and logs; every invocation checks actual current test bytes. These receipts establish local content consistency, not independently authenticated truth or same-UID confinement. Original H01 test/evidence artifacts remain unchanged; H02 witnesses them again against exact preserved legacy source.

Context routes inspect committed, staged, unstaged and untracked paths. Root routes describe this kit; consumer routes cover only installed governance. Pack servers use OS-assigned ports, bounded readiness and owned-process cleanup. Status requires a real local check and validates observed remote rule contents; API failures remain indeterminate. Core startup and full verification have distinct documented prerequisites.

Revisit these choices when an independently verified runtime receipt/authority protocol replaces local witnesses, when the supported parser version changes, or when a consumer explicitly adopts a new profile. No baseline, remote rule change or product deployment is approved by these local results.
