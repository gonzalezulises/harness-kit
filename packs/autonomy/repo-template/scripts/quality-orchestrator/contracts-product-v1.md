# Bounded product objective v1

`openRuntime({product, journal:{contract:'product.v1', ...}, ...})` installs a
closed supervisor. `describeProductObjective(input,ctx)` freezes the accepted
normative context, exact base commit, complete separate product inventory,
mutable/frozen paths, outcome, typed acceptance/regression cases, coverage,
expiry, step budget, toolchain and verifier. The owner signs its digest with the
existing `bounded-grant` envelope and the product scope digest. This is a new
subject domain; it does not reinterpret H06 semantic equivalence.

`bindProductObjective({objective,approval},ctx)` returns a private handle.
`runProduct(handle)` consumes its next bounded operation without copying model
outputs between steps. `nextProductStep`, `executeProductStep(handle,key)` and
`resumeProductStep` provide the same single-step/resume path. There is no public
observation importer. Candidate prose or a supplied PASS boolean cannot write
verified state. Commands are one host-pinned Node verifier plus the existing
fixed Codex stdio worker. Shell text, arbitrary argv, inherited environment and
candidate-selected executables are not accepted. The worker proposes exact
before/after file bytes as data; the supervisor applies them separately.

A new journal opts into the product event decoder/runtime binding. Its sole
additional internal operation references a persisted product payload and prior
product digest. It reuses the existing object store, append/CAS, lock and replay;
the public journal cannot append product operations. Historical v1 event/run/
witness schemas and JOURNAL_RUNTIME_BINDING remain exact. Product starts spend
the same objective total with separate explicit fullReview/fix/control counters,
not a mechanical-write/review category. Product journals currently remain local
unwitnessed; external checkpoint support is unavailable.

The lifecycle verifies bound/scoped prerequisites before RED, then dispatches
AUTHOR, PATCH, VERIFY and one independent FULL review. Open Critical/High or
AC-invalidating findings block progress. Reproducible findings name an already
approved regression case. The same pinned verifier observes a causal RED before
a fix, then GREEN at corrected bytes; a FOCAL review references the original
FULL and the exact current source/diff/coverage. At most two fix starts are
charged, including unsuccessful attempts. Medium/Low findings without an
AC-invalidating counterexample remain visible in the handoff backlog.

The verifier emits `{version:1,cases:[{id,actual}],identity}`. The supervisor
compares each actual value to signed expected values, checks exit consistency,
requires the exact case set and requires version, manifest and applicable
schema-state identity. Health/load alone is UNKNOWN. A configured verifier is
trusted executable capability: its digest, runtime, argv and allowed environment
are part of the grant. It is not a model-generated checker.

Malformed verifier UTF-8 rejects the supervisor promise with BLOCKED_TOOL_FAILURE.
The original charged pending operation remains resumable; without an observed
result, resuming does not start that verifier again. Strict decoding failure
does not escape the child close callback or terminate the controller.

Model author and reviewer use separate fresh source/home/scratch directories and
separate authenticated app-server sessions. Source remains read-only to the
model; primary bytes are rechecked after awaits. This module does not create OS
containment or copy credentials. `UNAVAILABLE` blocks before spend. `FIXTURE`
permits explicit protocol fixtures only and cannot produce P0_READY. A real host
requires an enrolled execution-supervisor attestation of its tested containment
and frozen configuration, plus functioning model authentication inside the
operator-provided environment. An attestation is the operator's trust boundary,
not proof generated by this module.

A step nonce is journal-owned before any effect. Competing processes cannot
start it twice. Completed observations are retained separately before progress
append and reused on resume at exact bindings. Unknown pending outcomes do not
redispatch. Patch writes require exact before bytes and frozen-path checks under
journal custody. Host isolation must prevent unrelated concurrent writers; a
same-UID hostile filesystem is not made safe by a JavaScript lock.

Desired, observed, verified and reported state are separate projections. Claims
carry their provenance class. Known differences are monotonic blockers for slice
approval, PASS, next slice and baseline promotion. They cannot be erased by a
caller-supplied boolean; an unresolved difference requires a new authorized
resolution. Two control-only cycles without RED or tested product change stop
normal progress. Baseline acceptance remains an owner action.

The final local PR preparation creates commit objects in an isolated Git
repository with exact paths, a fixed supervisor identity, base parent and title/
body/receipt. It does not touch the source index, source refs or any remote.
`HANDOFF_PREPARED` means the local artifact is prepared, not that a PR exists or
merge is approved. `prCreated:false`, actual PR readiness UNKNOWN and real
completed-objective count zero remain explicit. Fixture completions have their
own counter. Unmeasured metrics are UNKNOWN. No merge, deployment or production
operation is part of this contract.

Review correction 1: product admission and INTENT replay require the bound run
still OPEN. In-flight observations remain evidence, but an open difference keeps
canonical verification UNKNOWN. A typed functional VERIFY RED settles its nonce
and enters the same bounded FIX path; it is not treated as an uncertain effect.

Findings retain their original identity and first review reference. Every omitted
C/H still needs its own approved case, observed RED, current case GREEN and focal
reference before closure. Partial closure persists across rounds; unresolved
findings and Medium/Low backlog survive focal omission. One case cannot borrow
another case's failure.

Coverage rows contain invariantId, surface, mutationPath, principal,
negativeTestId, applicability and basis. Required surfaces are CLI, UI,
API_SERVER_ACTION, RPC, DIRECT_DML_POSTGREST, BATCH_SYNC, STORAGE, TRIGGERS,
MIGRATIONS and PRIVILEGED_CLIENTS. Each absent surface needs its own N/A row and
reason; N/A has no case or evidence claim. Applicable rows name a scoped path
and an approved test case. The runtime derives observedResult and evidenceDigest
from current manifest-bound GREEN observations; missing observations block PASS.
The pilot has one CLI surface. It has no browser, HTTP API/server action, RPC,
SQL/PostgREST, batch/sync, storage service, trigger, migration or privileged
application client. Supervisor permissions are covered by separate harness tests.

Local PR preparation resolves Git's absolute common directory, including linked
worktrees. The isolated object database reads base objects from that directory;
prepared parent and frozen tree entries are checked without modifying the source
index, references, HEAD or frozen worktree bytes. This remains a local handoff
and does not assert that a remote PR exists.
